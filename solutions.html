The user-facing product layer

Solutions are what people discover, launch, and trust.

A ContextWeaver Solution is the final user-facing composition: a complete experience, dependency graph, lifecycle, and set of reusable Services assembled from governed Workflows, Agents, MCP capabilities, knowledge, models, and policy.

The critical distinction

Service is the reusable executable contract. Solution is the complete user experience.

A Service can support many Solutions. A Solution can compose multiple Services. Solutions reuse the existing Service Run API; they do not create a separate runtime primitive.

Conceptual model

Five concepts. Five different responsibilities.

Each layer adds meaning without erasing the layer beneath it. The distinction keeps reasoning, tool access, orchestration, executable contracts, and user experience independently governed and reusable.

01 · MCP capability

A governed way to reach a tool or source

Defines tools, resources, prompts, schemas, delegated identity, side-effect risk, receipts, rate limits, idempotency, and compensation. It does not decide the business goal.

02 · Agent

A bounded reasoning specialist

Uses an approved model, instructions, knowledge, skills, and MCP allow-list to perform one typed responsibility. It does not own end-to-end durable coordination.

03 · Workflow

A durable coordination graph

Sequences and joins typed work across Agents, MCPs, waits, approvals, events, retries, checkpoints, and compensation. It defines how work progresses and recovers.

04 · Service

A reusable executable intent-to-outcome contract

Publishes stable inputs, outputs, policies, SLOs, ownership, lifecycle, and one or more approved Workflows. It is the unit launched through the Service Run API.

05 · Solution

The final user-facing composition

Combines one or more Services with the complete dependency graph, presentation, entry actions, lifecycle, entitlement, and Service Experience Contract that a consumer sees.

Plain-language model

A restaurant, not a pile of kitchen equipment.

MCP capabilities are the appliances and supplier interfaces. Agents are skilled specialists. Workflows are the coordinated kitchen process. Services are reusable menu-item contracts the kitchen can reliably produce. The Solution is the complete restaurant experience the customer discovers, orders from, follows, and evaluates.

One authentication entry point

The same platform presents the right experience for each user.

Entitlements determine presentation after sign-in. Consumer users do not need to navigate internal MCPs, Agents, Workflows, or cluster resources, while builders and operators retain the detailed controls they need.

Consumer

My Solutions

Consumer-only users land on /my-solutions, discover permitted Solutions, launch experience actions, provide inputs, approve when required, and inspect status, results, history, citations, and receipts.

Builder / Admin

Studios and operations

Authorized builders create and qualify MCPs, Agents, Workflows, Services, and Solutions. Operators manage identity, policy, publication, runtime health, evidence, and lifecycle.

Headless / delegated

Copilot, Claude, API, or event

External assistants discover and invoke only the Solutions and actions allowed for the represented user. Delegated identity is preserved end to end; provider credentials remain platform-owned.

Consumer journey

From sign-in to evidence-backed result.

The user journey stays simple because the platform preserves the complexity and proof beneath it.

Sign in once

ContextWeaver resolves tenant, user, role, groups, relationships, purpose, session, device, and current entitlement state.

Open My Solutions

The portal returns only published Solutions currently permitted for this user and context.

Choose an experience action

The Service Experience Contract renders approved fields, guidance, progress, approval points, result views, and evidence links.

Launch the Service Run

The action maps to a reusable Service and approved Workflow. The runtime freezes exact capability, policy, source, model, and configuration versions.

Follow progress and approve

Durable state survives waits and failures. Human authority is requested explicitly when policy requires it.

Receive the result and proof

The Solution presents the outcome with appropriate citations, receipts, approvals, lineage, run history, and trace links.

External assistants on behalf of a user

Delegation changes the channel—not the authority model.

A Copilot, Claude client, IDE extension, or another approved assistant does not receive a master key or bypass the consumer model.

Discover

Identity-filtered catalog

The capability gateway returns only Solutions, Services, and actions allowed for the represented user, tenant, purpose, and channel.

Delegate

Bound user context

Short-lived delegated context carries the user, client, scope, purpose, correlation, and revocation state into each protected request.

Invoke

Same policy and runtime

The gateway reauthorizes the exact action and arguments, then launches the same governed Service Run used by the portal.

Return

Minimized result and evidence

The assistant receives only the permitted result and references. Connector, cloud, model-provider, and database credentials never enter its context.
