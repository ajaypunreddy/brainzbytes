What can be created

Four asset types, designed to work together.

The Studio makes the distinction clear so a tool is not confused with an Agent, and a Workflow is not mistaken for an unrestricted chat chain.

Specification

The contract

Identity, owner, inputs, outputs, errors, side effects, data classes, dependencies, SLOs, tests, support, and lifecycle.

Agent

The reasoning capability

A bounded task specialist with typed inputs and outputs, approved model envelopes, skills, evaluations, and resource limits.

MCP

The tool capability

A governed integration exposing tools, resources, and prompts with schemas, delegated identity, side-effect classes, receipts, and compensation.

Service + Workflow

The customer outcome

An executable product that composes typed steps, parallel work, decisions, waits, approvals, callbacks, retries, and finalization.

Plain-language model

A workshop with an inspection window.

The Studio does not hide what it generates. It is closer to a workshop where every drawing, part, test, safety check, and release package remains visible. Non-programmers get guidance; engineers can open the exact specifications, schemas, code, policies, and deployment assets.

Studio workspace

Designed for hundreds of capabilities, not a handful of cards.

Separate Agent and MCP catalogs support search, ownership, lifecycle, risk, health, version, environment, dependency, and entitlement filters.

Agent catalog

Find the right specialist

  • Search by capability, owner, domain, trust, region, model envelope, and evaluation
  • Compare exact versions, schemas, SLOs, support, and consumers
  • Inspect Agent Cards, dependencies, dashboards, and recent runs
  • Create, clone, modify, deprecate, drain, or retire through governed actions
MCP catalog

Find the right tool boundary

  • Search by tool, provider, side-effect class, data scope, credential profile, and region
  • Inspect schemas, transports, rate limits, idempotency, receipts, and compensation
  • See every Service, Workflow, and Agent consumer before an update or removal
  • Test through a safe sandbox without exposing provider credentials to the Agent
