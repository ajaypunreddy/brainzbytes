AWS mapping

Equivalent managed services beneath Kubernetes contracts

The deployment must preserve the same durability, security, identity, network, evidence, and recovery invariants.

IdentityIAM Identity Center or an approved external OIDC provider for users; EKS Pod Identity or IRSA for workloads.
ComputePrivate Amazon EKS with isolated node groups for system, control, execution, RAG, gateway, and capability workloads.
Durable stateAmazon RDS for PostgreSQL or Aurora PostgreSQL with Multi-AZ, backups, PITR, pgvector, and tested failover.
MessagingRabbitMQ quorum queues on EKS or Amazon MQ for RabbitMQ after compatibility, durability, performance, and recovery validation.
ArtifactsAmazon S3 with versioning, encryption, retention, tenant prefixes, immutability controls, and lifecycle policies.
SecretsOpenBao/Vault as portable broker, optionally integrated with AWS Secrets Manager, KMS, and External Secrets.
ModelsAmazon Bedrock or approved external providers behind the same Model Gateway policy, redaction, budget, and evidence contracts.
SearchPostgreSQL FTS + pgvector first; OpenSearch only when measured workload characteristics require distributed search.
EdgeCloudFront, WAF, and ALB/NLB or a supported Kubernetes ingress/gateway, with private service and data endpoints.
OperationsPrometheus, Grafana, Loki, OpenTelemetry, CloudWatch integration, immutable audit, SLOs, and recovery exercises.
Non-negotiable invariants

Portability does not weaken the architecture

No synchronous Agent chain

Agents consume durable commands and publish events or typed MCP intent through RabbitMQ.

No credentials in Agents

Trusted gateways obtain short-lived scoped authority; Agent pods have no direct provider or MCP route.

No pod-local run ownership

Runs, tasks, leases, checkpoints, timers, HITL, receipts, and compensation remain in durable stores.

No cloud-specific workflow logic

Workflows reference capabilities and contracts, never AWS service endpoints or credentials.

No unmeasured search migration

PostgreSQL remains the default RAG tier until latency, scale, or feature evidence requires expansion.

No unverified failover claim

Queue, database, object, identity, network, and worker recovery must pass fault-injection tests.
