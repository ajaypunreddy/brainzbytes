ContextWeaver NextGen · Architecture target

Durable, governed AI services — not a synchronous chatbot chain

ContextWeaver accepts typed work, freezes an authorized execution plan, commits it to PostgreSQL, dispatches commands through RabbitMQ, and lets replaceable workers execute Agents, RAG, models, approvals, and MCP effects safely across pod failures.

Platform planes

One platform, separated by durable and security boundaries

The architecture scales each responsibility independently. Browser sessions and Kubernetes pods never own a run.

Prompt to result

The synchronous request ends after durable admission

Everything after acceptance is resumable, observable, and independent of the browser or accepting API pod.

01 REQUEST

Authenticate and validate

Resolve tenant, principal, purpose, schema, and idempotency.

02 PLAN

Compile and authorize

Freeze the typed DAG, versions, capabilities, policy, and budgets.

03 COMMIT

Create durable run

Atomically persist run, plan, first tasks, and pending outbox.

04 ACCEPT

Return HTTP 202

Return runId, statusUrl, and eventsUrl after the commit succeeds.

05 DISPATCH

Publish commands

Confirmed outbox publishers send persistent RabbitMQ messages.

06 EXECUTE

Lease and checkpoint

Workers reauthorize, execute, commit outcomes, then acknowledge.

07 PROJECT

Stream durable events

Clients reconnect and replay progress, HITL, evidence, and results.
