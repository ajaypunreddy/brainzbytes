One governance thread

From approved intent to a verified result.

ContextWeaver separates what an AI model may propose from what the platform will authorize and execute. The typed plan, current identity, policy, credentials, runtime state, and evidence stay connected end to end.

Bring public MCPs into governance

Use public Docker MCP servers without surrendering your control plane.

ContextWeaver adapts standard public MCP images behind a normalized gateway. Administrators configure organization connections once; authorized users can call approved tools without viewing or owning provider credentials.

MCP lifecycle guide Credential model
ImportPin the public image and declare stdio or Streamable HTTP transport.

Trust is runtime behavior

The model is not the authority.

Models can draft and reason. They cannot grant themselves access, choose hidden endpoints, reveal credentials, approve their own work, or convert a read-only entitlement into side-effecting authority.

Identity

Authority stays attached

Every protected request carries verified user, tenant, role, group, and purpose context.

Policy

Exact graph decisions

Authorization covers the selected capability, resource, action, data, side effect, and current entitlement.

Credentials

Agents never possess secrets

Trusted gateways broker scoped runtime access; users and Agents receive outcomes, not provider keys.

Evidence

Every run can be examined

Decisions, grants, receipts, revisions, attempts, citations, metrics, logs, and traces remain reviewable.
